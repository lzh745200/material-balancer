# 项目文件结构说明（写给第一次看这个项目的人）

> 不用担心，这份文档不要求你懂 Electron 或 Vue，只用大白话讲清楚：
> **每个文件夹/文件是干什么的、改哪个文件会影响什么、数据是怎么流动的。**
>
> 这个项目是一个「物资均衡分配工具」：把一份物资清单（如 笔记本 ×10、钢笔 ×20）
> 尽量公平地分给一群人，然后生成可以打印出来签字的 A4 表格。

---

## 一、先建立大局观：三个进程

Electron 应用就像一个「三人小组」：

| 角色 | 类比 | 代码位置 | 能做什么 |
| --- | --- | --- | --- |
| **主进程** (main) | 管家 | `src/main/` | 干所有「碰系统」的活：读写文件、弹对话框、打印、生成 PDF |
| **中间人** (preload) | 传话筒 | `src/preload/` | 只有它一个文件，负责把主进程的能力「安全地」递给界面 |
| **渲染进程** (renderer) | 界面 | `src/renderer/` | 你眼睛看到的一切：按钮、表格、拖拽，以及分配算法 |

**为什么要分三个？** 安全。界面代码是「网络上最容易被攻破的部分」，所以它被关在笼子里
（沙箱），不能直接碰你的硬盘；每次想读写文件，都要通过中间人向主进程「申请」。

**共享契约**：三个进程都遵守同一份数据格式和「暗号」（IPC 通道名），写在
`src/shared/`，谁也不能私自改。

## 二、目录树逐行注释

```
material-balancer/
├─ .github/workflows/build.yml    # 自动构建流水线：推送代码后 GitHub 云端
│                                 #   先跑「代码体检」（lint/类型检查/测试），
│                                 #   全过了才打包 Windows 和 Linux 安装包
├─ .npmrc                         # npm 配置：Electron 下载走国内镜像（加速）
├─ .nvmrc                         # 声明本项目用哪个 Node.js 版本（20）
├─ electron-builder.yml           # 「打包说明书」：怎么把代码做成 .exe 安装包
├─ electron.vite.config.ts        # 构建配置：告诉打包器主/中/界面三部分各自的入口
├─ eslint.config.mjs              # 代码风格检查器配置（自动发现低级错误）
├─ vitest.config.ts               # 测试配置（@ 别名指向哪里、哪种测试用哪种环境）
├─ package.json                   # 项目身份证：名字、版本号、所有依赖、可用命令
├─ tsconfig.*.json                # TypeScript 编译器的两套检查规则（主进程/界面各一套）
│
├─ build/                         # 应用图标（.ico 给 Windows 用，.png 通用）
├─ resources/fonts/               # 打印用的中文字体（思源黑体）——保证任何电脑上
│                                 #   打印出来的表格字体都一样，不依赖系统字体
├─ scripts/gen-icons.mjs          # 小工具：运行 npm run icons 可重新生成图标
└─ out/ & dist/                   # 构建产物（自动生成，不用手动改，已加入 .gitignore）
```

### `src/shared/` —— 两个进程的「共同语言」（很小但很重要）

| 文件 | 一句话说明 |
| --- | --- |
| `types.ts` | 所有数据长什么样（物资、人员、分配方案…）+ 所有「暗号」常量。想新增一种数据，先来这定义 |
| `validate.ts` | 打开外部文件时的「安检仪」：逐条检查数据合不合法，坏的剔除而不是崩溃 |

### `src/main/` —— 管家（所有碰系统的事）

| 文件 | 一句话说明 |
| --- | --- |
| `index.ts` | 程序入口：创建窗口、拦截危险跳转、**关窗时如有未保存内容先弹确认** |
| `menu.ts` | 顶部应用菜单：Ctrl+N/O/S/P 等快捷键在这里注册，按下后「传话」给界面执行 |
| `services/atomic.ts` | 一个 12 行的小工具：先写临时文件再改名，保证写文件写到一半断电也不会损坏 |
| `services/fileIO.ts` | 文件总管：打开/保存项目、导入 CSV/Excel、导出 PDF/Excel/CSV、最近文件列表的登记处 |
| `services/parse.ts` | 翻译官：把 CSV/Excel 原始内容翻译成「物资列表」「人员列表」。处理 GBK 编码、表头识别、全角数字等脏活 |
| `services/draft.ts` | 草稿管理员：每 1.5 秒把当前内容存进本地草稿，程序崩溃后可恢复 |
| `services/recents.ts` | 最近打开的 10 个项目文件的记忆本 |
| `services/pdf.ts` | 打印/导出 PDF：在一个看不见的窗口里渲染表格 HTML，再让 Chromium 打印成 PDF |
| `services/template.ts` | 生成「导入模板.xlsx」（物资表+人员名单两个空表+示例行），给用户照着填 |

### `src/preload/index.ts` —— 传话筒（只有一个文件）

把主进程的能力包装成 `window.api.xxx()`（如 `window.api.saveProject()`），
界面只能调用这些包装好的方法，不能干别的。**想新增一个「界面→主进程」的功能，
要同时改三处：`shared/types.ts`（暗号）→ `main/services/fileIO.ts`（实现）→ 这里（包装）。**

### `src/renderer/src/` —— 界面（你看到的和算的全在这）

```
renderer/src/
├─ main.ts                 # 启动引导：加载 Vue、组件库、全局样式
├─ App.vue                 # 页面骨架：上=工具栏，中间三栏，下=状态栏；草稿恢复弹窗也在这
│
├─ stores/project.ts       # ★ 全项目唯一的数据仓库（Pinia）
│                          #   物资/人员/方案、撤销重做、生成/拖拽/锁定……
│                          #   界面上任何按钮最终都会改这里的数据
│
├─ algorithms/             # ★ 分配算法（纯数学，不碰界面，可独立测试）
│   ├─ expand.ts           #   「笔记本×3」拆成 3 个独立件（分配的最小单位）
│   ├─ greedy.ts           #   贪心：最贵的先分给当前拿得最少的人
│   ├─ optimize.ts         #   优化：反复「挪一件/换两件」缩小贫富差距
│   ├─ random.ts           #   随机模式：洗牌+贪心+优化，抽多轮取最好
│   ├─ stats.ts            #   算平均/最高/最低/差值/标准差/未分配数
│   └─ index.ts            #   总入口 distribute()
│
├─ components/             # 界面零件（每个 .vue 是一块屏幕区域）
│   ├─ AppToolbar.vue      #   顶部工具栏：新建/打开/保存/导入/生成/导出
│   ├─ MaterialPanel.vue   #   左栏：物资表格（增删改、搜索）
│   ├─ PersonPanel.vue     #   中栏：人员列表
│   ├─ ResultPanel.vue     #   右栏：分配结果、未分配池、方案历史入口
│   ├─ PersonCard.vue      #   单个人员卡片：物资标签、拖拽、参与开关、锁定
│   ├─ StatsSummary.vue    #   统计条（平均值等 6 个数字）
│   ├─ StatusBar.vue       #   底部状态栏（文件名、件数、未分配警告）
│   └─ dialogs/            #   弹窗：SettingsDialog（设置）、SchemeHistoryDialog（方案历史）
│
├─ composables/            # 可复用的「行为包」（Vue 的组合式函数）
│   ├─ useProjectActions.ts#   用户动作总集合：打开/保存/导入/导出…工具栏和菜单共用
│   ├─ useGenerate.ts      #   点「生成方案」后的统一反馈（成功提示/超差提醒）
│   ├─ useDraftAutosave.ts #   自动存草稿 + 关窗兜底 + 向管家上报「有没有未保存修改」
│   └─ useShortcuts.ts     #   Ctrl+Z 撤销 / Ctrl+Y 重做
│
├─ print/                  # 打印模块
│   ├─ rows.ts             #   把分配结果整理成「每人一组」的行数据（打印/导出共用）
│   └─ buildPrintHtml.ts   #   拼出 A4 表格 HTML（转义防注入、分页保护 CSS）
│
└─ utils/                  # 小工具
    ├─ format.ts           #   金额格式化（¥1,234.50）、日期
    ├─ csvExport.ts        #   生成 CSV（防 Excel 公式注入）
    ├─ xlsxExport.ts       #   生成 Excel 双表（明细+汇总）
    └─ id.ts               #   生成不重复的 id
```

### `tests/` —— 测试（86 个用例，改代码的「安全网」）

| 文件 | 测什么 |
| --- | --- |
| `algorithms.spec.ts` | 算法：均衡性指标、确定性（同输入必同输出）、500 件 3 秒内 |
| `store.spec.ts` | 数据仓库：增删改、撤销重做、各种非法输入要被拒绝 |
| `io.spec.ts` | 解析与导出：CSV/Excel 各种脏格式、文件校验、打印 HTML |
| `components/panels.spec.ts` | 界面冒烟：添加物资/人员的校验联动 |

## 三、数据是怎么流动的（以「点击生成分配方案」为例）

```
[你点按钮]
   ↓ AppToolbar / ResultPanel → useGenerate()
   ↓ stores/project.ts → generateAllocation('optimized')
   ↓ algorithms/index.ts → distribute()
        ① expand.ts     拆件        （笔记本×3 → 3 件）
        ② greedy.ts     先贪心      （最贵的给拿得最少的）
        ③ optimize.ts   再优化      （挪一件/换两件缩小差距）
        ④ stats.ts      算统计      （差值、标准差…）
   ↓ 存入 store 的新方案
   ↓ Vue 响应式自动刷新 → 右栏人员卡片、统计条、状态栏全部更新
   ↓ 1.5 秒后 useDraftAutosave 静默存一份草稿
```

而「打开文件」则是另一条路，会跨进程：

```
[你点「打开」]
   ↓ window.api.openProject()          （界面请求，走传话筒）
   ↓ 主进程弹系统文件对话框，读磁盘
   ↓ shared/validate.ts 安检           （坏数据剔除）
   ↓ 传回界面 → store.loadProject()    （一次性的快照，不进撤销历史）
```

## 四、常见任务速查：改哪儿？

| 你想… | 去改 | 注意 |
| --- | --- | --- |
| 改界面文字/按钮 | `renderer/src/components/` 对应 .vue | 中文文案直接搜 |
| 调分配算法 | `renderer/src/algorithms/` | 改完跑 `npm test`，均衡性有硬指标 |
| 加一种数据字段 | `shared/types.ts` + `shared/validate.ts` + store | 三个地方要同步 |
| 加一个「菜单里的功能」 | `shared/types.ts`(暗号) → `main/`(实现) → `preload/`(包装) → `composables/useProjectActions.ts`(执行) | 四步缺一不可 |
| 改打印表格样式 | `renderer/src/print/buildPrintHtml.ts` | 分页 CSS 别删 |
| 改打包配置 | `electron-builder.yml` | 改完推送看 CI 产物 |
| 升版本号 | `package.json` 的 `version` | 打 tag 发布时 CI 会校验与 tag 一致 |

## 五、必会命令

```bash
npm install        # 第一次：装依赖
npm run dev        # 边改边看效果（热更新）
npm test           # 跑 86 个测试——改完代码必跑
npm run typecheck  # 类型检查——低级错误现形
npm run lint       # 风格检查
npm run build      # 正式构建到 out/
```

> 记住一条黄金法则：**数据只住在 store（`stores/project.ts`），界面是它的镜子，
> 算法是它的加工厂，主进程是它唯一被允许触碰外部世界的信使。**
