# 物资均衡分配工具 — Bug 修复与功能完善计划

基于 3 个并行检测代理对全部源码的审查（算法/store、主进程/数据管道、UI/测试/CI，共 33 个文件），计划分 4 个阶段，每阶段结束跑 `npm test` + `npm run typecheck` 验收。

## 检测结论（已抽查证实）

**高危 bug（10 个）**：
1. `fileIO.ts:38` — `validateProject` 接受 `assignment: null`（`typeof null === 'object'`），打开恶意/损坏文件后 `moveUnit`/`isStale` 直接 TypeError 崩溃
2. `optimize.ts:45,140`、`random.ts:51` — 用 `Date.now()` 墙钟截断搜索，同一输入在不同机器/负载下结果不确定，违背模块自述的确定性契约
3. `project.ts:104-112` — `isStale` 只检测悬空引用，数量调大后新增件（`m1#3`）静默不参与统计与打印
4. `project.ts:239-246` — `updateMaterial` 无数量上限，绕过 5000 件上限后 `units` getter 落入静默 50 件/物资截断兜底（`project.ts:69-76`）
5. `main/index.ts:52` — 关窗无未保存确认；`useDraftAutosave.ts:35` 的 beforeunload 兜底是异步 `invoke`，关窗时可能丢失
6. `draft.ts:12-23` — 草稿写入失败被吞掉，主进程仍 resolve 成功，UI 照常显示"草稿已自动保存"；且写入非原子，崩溃可致草稿截断
7. `project.ts:213-225` — `loadProject` 零运行时校验，`title: undefined` 会让 `defaultFileName` 抛异常
8. `parse.ts:63-69` — 无表头 CSV/XLSX 首行若价格列空白/不可解析，整行被当表头静默丢弃（不计入 skipped）
9. `parse.ts:113-126` — 人员名单 CSV 含表头时，"姓名"被导入为一个人
10. `pdf.ts:64-67` — 打印失败 `NotaMemberOfAppGroup` 被当成功，用户点了打印无输出且无报错

**中危（12 个）**：`toNumber` 不支持全角数字/逗号（`parse.ts:53`）；表头正则 `金额` 误当单价、首行空白行破坏列探测；打印临时文件固定名竞争且永不删除（`pdf.ts:36`）；xlsx 只认扩展名不看 `PK` 魔数、固定取 Sheet[0]；PapaParse errors 被忽略；`totalValue` 与件数展开口径不一致（数量 2.5）；手动添加/重命名允许重名（导入却去重，行为不一致）；方案名可重复、撤销跨 30 方案上限后 activeSchemeId 悬空显示全零统计；`moveUnit` 不验证 unitId 存在；CSV 导出公式注入（`=HYPERLINK`）+ 币种符号未转义破坏表头；store 接受负价格/0 数量；stats 无"未分配件数"信号。

**低危（顺手修）**：默认文件名用 UTC 日期（UTC+8 晚间存成昨天）；标准差缺货币符号；`newProject` 不重置 draftSavedAt；策略 switch 无 assertNever；非空断言补防御检查。

**功能缺口**：无 Ctrl+S/O/N/P 快捷键（菜单被置 null）、无最近文件、保存无 .bak、无人员排除/未分配池/手动锁定重优化、无 XLSX 结果导出、打印无页码且人员块跨页断裂、CI 无 typecheck、零组件测试、无 ESLint。

## 阶段 1：Bug 修复（约 30 项，全部带回归测试）

### 1.1 主进程与数据管道
- **`fileIO.ts`**：`validateProject` 改为 `s.assignment !== null && typeof s.assignment === 'object'`，并逐项校验 assignment 值为 string、material price 为有限正数、quantity 为 ≥1 整数（与导入解析同口径）；`ProjectSaveToPath` 改临时文件+rename 原子写；`DraftSave` 返回 `{ok, error}` 不再吞错；打开对话框去掉 `BrowserWindow.fromWebContents(e.sender)!` 非空断言（降级为无主窗调用）。
- **`draft.ts`**：写草稿改临时文件+rename；`readDraft` 增加 JSON 完整性探测（可 parse 且含 materials 字段才返回，否则报"草稿损坏"）；`newProject` 重置 draftSavedAt（store 侧）。
- **`parse.ts`**：`toNumber` 归一化全角数字 `０-９`、全角逗号/句点；表头探测先跳过首部全空行；单价列优先级 `单价 > 价格 > 金额`（仅当无高优先级命中才用 金额）；`parsePeople` 增加表头容忍（首列匹配 `姓名|name|人员` 时跳过）；无表头判定时不再丢行——首行按数据计入 skipped 并提示；把 PapaParse `errors` 汇总返回并在导入 toast 中显示"跳过 N 行（原因）"。
- **`fileIO.ts` 导入分发**：按 `PK\x03\x04` 魔数识别 xlsx（而非仅扩展名）；`parseMaterialsXlsx` 取第一个含数据的 sheet，全空时报"未找到数据表"而非静默空结果。
- **`pdf.ts`**：临时文件改 `fs.mkdtemp` 唯一目录并在完成后清理；`did-finish-load` 后经 `executeJavaScript('document.fonts.ready')` 等待字体替代固定 300ms；`NotaMemberOfAppGroup` 与其他失败原因 reject 并由 UI 弹错误；`ExportPdf`/`ExportPrint` 复用同一窗口创建逻辑避免竞争。
- **`main/index.ts`**：`setWindowOpenHandler` 一律 deny、`will-navigate` deny（离线加固）；`index.html` 加 CSP meta；**关闭确认**：renderer 通过轻量 IPC `project:dirty-changed` 同步 dirty 标志到主进程缓存，`win.on('close')` 时若 dirty → `showMessageBox` 三选（保存/不保存/取消）；**关窗兜底保存**改用 `ipcRenderer.sendSync` 专用同步通道（仅 beforeunload 用），杜绝异步丢失。
- **CSV 公式注入**（`csvExport.ts`）：`cell()` 对以 `= + - @ \t` 开头的值前缀 `'` 转义；币种进入表头前转义。

### 1.2 渲染进程 store 与算法
- **`project.ts`**：
  - `loadProject` 增加运行时归一化（与 validateProject 同规则：缺省 title/currency、过滤非法 material/person/scheme、assignment 值非 string 剔除），不再盲信类型
  - `isStale` 语义扩展：`悬空引用 || 存在未分配的现有件`，配合 stats 新增 `unassignedCount`；`ResultPanel` 提示文案改为"当前方案未覆盖全部物资（N 件未分配/存在失效引用）"
  - `updateMaterial`：数量取整 ≥1，且校验新增件数不超 MAX_UNITS 余量（复用 wouldExceedUnitLimit 逻辑）；price 非有限或 ≤0 时拒绝该字段 patch；`addMaterial` 同样归一化
  - `units` 兜底分支：去掉 50 魔数截断，改为遵守 MAX_UNITS 并置 `unitsTruncated` 标志供 StatusBar 显示警告（正常情况下 1.2 的编辑守卫使其不再触发）
  - `totalValue` 与 `unitCount`/`expandUnits` 统一为 `Math.max(1, Math.floor(m.quantity || 1))`
  - `moveUnit` 校验 unitId 在 unitMap 中，并支持 `toPersonId: null` 落入未分配池（为阶段 3B 铺路）
  - `restore()` 后若 activeSchemeId 悬空则回退到最后一个方案；方案命名改为"取现有最大编号+1"避免重名
  - `defaultFileName` 改本地日期（`format.ts` 新增 formatDate）
- **`optimize.ts`/`random.ts` 确定性**：主预算从墙钟改为**确定性操作计数**（maxOps，评估候选数上限），墙钟仅保留 8s 应急止损（命中时 console.warn 文档说明非确定）；`random.ts` 每次重启同样用 maxOps；补两个 500 件级"两次运行结果全等"的确定性测试。
- **`stats.ts`**：GlobalStats 增加 `unassignedCount`、`coverage`（已分配件数/总件数）；`Math.max(...)` spread 改 reduce 防极端参数上限；空 personIds 防御。
- **`algorithms/index.ts`**：策略 switch 加 `assertNever`。

### 1.3 UI 组件
- `PersonPanel`/`MaterialPanel`：手动添加与重命名做重名校验（ElMessage 提示），与导入去重行为对齐；`MaterialPanel.saveEdit` 补数量上限与合法价格守卫
- `AppToolbar`/`ResultPanel`：生成逻辑抽成单一 store action `generateAndReport(strategy)`（消除两处重复），超差提示只保留内联 alert + 一次性 toast，去掉重复模态
- `StatsSummary` 标准差补货币符号；`PersonCard` dragover 仅在 dataTransfer 含自定 unit 类型时高亮（防止文件拖入假高亮）
- `StatusBar` 增加"未分配 N 件"与 unitsTruncated 警告显示

### 1.4 回归测试（tests/ 全部为纯逻辑，沿用 vitest node 环境）
- algorithms：数量归一化（0/负/小数/NaN）、greedy 同价并列、optimize/random 双跑全等（大输入）、stats 未分配计数、脏输入跳过路径
- store：updateMaterial 钳制、isStale 数量增加/清空方案、ghost unitId、方案上限驱逐+undo 回退、重名方案、loadProject 畸形数据、exportProject 深拷贝独立性、wouldExceedUnitLimit
- io：validateProject null assignment、人员表头跳过、全角数字、首空行、单价/金额优先级、CSV 注入转义、PK 魔数分发
- print/rows：空人员分支、悬空 unitId 行

## 阶段 3：功能完善（按优先级）

### 3A 基础体验（优先做）
1. **应用菜单 + 快捷键**：用标准 role 构建精简菜单（文件：新建/打开/保存/另存/打印 → Ctrl+N/S/O/P；编辑：撤销重做；视图：缩放/刷新/DevTools），菜单项经 IPC 调 renderer action 或直接 invoke 现有 handler，替换 `Menu.setApplicationMenu(null)`
2. **最近文件**：`userData/recents.json` 存最近 10 个 .mproj，工具栏"最近打开"子菜单 + 去重/失效清理
3. **保存备份**：覆盖保存时先写 `xxx.mproj.bak`（配合阶段 1 原子写）
4. **拖拽打开**：拖 .mproj 到窗口打开、拖 .csv/.xlsx 触发对应导入（走 will-navigate deny 的前提下在 renderer 处理 dragover/drop）
5. **物资表格搜索过滤**：MaterialPanel 加关键字过滤输入框

### 3B 分配能力增强
1. **按人排除**：`Person.active: boolean` + PersonCard 参与开关；distribute 前过滤，排除者不参与均衡
2. **未分配池**：生成策略支持"强制全分/允许剩余"选项（按价值均分到目标值，剩余留池）；未分配件在 MaterialPanel/ResultPanel 显示为可拖 chip，`moveUnit(unitId, null)` 拖出
3. **锁定 + 重优化**：scheme 增加 `locked: Set<unitId>`；"在当前方案上重新优化"调 `optimizeAssignment` 固定锁定件；一键解锁
4. **算法参数**：SettingsDialog 高级区暴露优化强度（maxPasses/maxOps）、随机重启次数、随机种子

### 3C 导出与打印增强
1. **XLSX 导出**：用现有 xlsx 依赖输出双 sheet（分配明细 + 按人汇总），复用 rows.ts 数据
2. **导入模板**：工具栏"下载导入模板"生成示例 CSV/XLSX
3. **打印改进**：`printToPDF` 用 `displayHeaderFooter` 加"第 X 页 / 共 Y 页"页脚；边距/标题在 SettingsDialog 可配置；人员块分页保护——块行数 ≤ 阈值时整块 `break-inside: avoid`，超阈值时每行重复姓名列（淡色）保证跨页可识别；`.foot` 签名行 `break-inside: avoid`
4. **人员名单支持 xlsx 导入**（单列）
